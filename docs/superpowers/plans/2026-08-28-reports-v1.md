# Отчёты v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Встроить в staging ERP защищённый ежедневный дашборд по ТП, отгрузке и остатку в цехе на основе таблицы «Отчеты Секретаря».

**Architecture:** Браузер обращается только к same-origin \`GET /api/reports/current\`. PHP API проверяет ERP-сессию и право \`reports\`, затем читает нормализованный срез через приватно настроенный Google Apps Script bridge; UI не получает URL bridge, токен или доступ к Google Sheets. Страница \`/reports\` показывает сводку, контролируемую детализацию и состояния загрузки/ошибки.

**Tech Stack:** Nuxt 4, Vue 3 Composition API, TypeScript, PHP 8, same-origin ERP API, Google Apps Script, Node contract tests.

**Spec:** \`docs/superpowers/specs/2026-08-28-reports-v1-design.md\`

## Global Constraints

- Только staging \`erp-mt.online\`; production не меняется.
- Google Spreadsheet \`1Y4HcpLRakc-aPWEwfF0PYmo5nzjj_0BLpbzqbtpqHvk\`, лист \`Лист15\`, только чтение.
- Не публиковать и не коммитить URL bridge, токен, ключи Google или учётные данные.
- TP берётся из H и отображается в рублях; отгрузка за месяц — J в тоннах; в цехе — G в тоннах.
- Пустые числовые ячейки нормализуются в \`0\`; неуспешный ответ источника не кэшируется как успех.
- Доступ API только при активной ERP-сессии и \`reports=true\`; без права — 403.
- Следовать TDD: тест → зафиксированное ожидаемое падение → минимальный код → зелёный тест.

## File Structure

- \`scripts/erp-gas-webapp.js\` — read-only bridge из Google Sheet, ответ только с нормализованными данными отчёта при корректном серверном токене.
- \`public/api/src/Reports.php\` — серверный ERP adapter: авторизация, запрос bridge, строгая нормализация и JSON-контракт ERP.
- \`public/api/src/Router.php\` — маршрут \`GET /reports/current\`.
- \`public/api/src/Bootstrap.php\` — загрузка report adapter в единую точку API.
- \`public/api/index.php\` — dispatch маршрута на report adapter.
- \`app/utils/erp-api.ts\` — typed client \`fetchReportsCurrentViaApi\`.
- \`app/utils/erp-sheets.ts\` — transport selector: SQL API в SQL-режиме, GAS rollback adapter в GAS-режиме.
- \`app/pages/reports.vue\` — живой экран дашборда вместо заглушки.
- \`app/components/erp/ErpReportsSummary.vue\` — три карточки руководительской сводки.
- \`app/components/erp/ErpReportsTable.vue\` — mobile-safe детализация.
- \`tests/reports-contract.test.mjs\` — регрессии API/UI/единиц/прав.
- \`tests/php/reports_test.php\` — PHP unit-level нормализация формата Sheets и отказ по невалидному bridge payload.

- [ ] **Step 3: Implement the minimal report adapter**

\`\`\`php
function erp_reports_current(PDO $pdo, array $config, string $requestId): void {
    $actor = erp_require_user($pdo, $config, $requestId);
    erp_require_permission($pdo, $actor, 'reports', $requestId);
    $payload = erp_reports_fetch_bridge($config);
    erp_json(200, ['ok' => true, 'data' => erp_reports_payload($payload)]);
}
\`\`\`

\`erp_reports_fetch_bridge\` uses cURL with short connect/read timeouts, URL-encodes token, rejects non-200/invalid JSON and maps source failure to one non-sensitive user message. \`erp_reports_payload\` sums normalised numbers and sets \`updatedAt\` from successful ERP read time and \`period\` to \`date('Y-m')\` in Moscow timezone.
