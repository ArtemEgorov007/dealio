# Раздел «Кадры»

## Цель

Заменить заглушку `/personnel` рабочим разделом управления сотрудниками из листа
`Сотрудники` таблицы «Доступ к серверу». Раздел доступен только сотрудникам,
у которых в колонке `Управление кадрами` стоит `Да`. Роль `Менеджер` не является
дополнительным ограничением.

## Данные и авторизация

Источник истины — лист `Сотрудники` в таблице доступа. GAS получает заголовок
динамически и ищет обязательные поля по именам: `ФИО`, `Отдел`, `Должность`,
`Площадка`, `Роль`, `Логин`, `Пароль`, `Статус`.

Права и доступы — все колонки начиная с K включительно. Клиент отображает их
по заголовкам, а сервер принимает изменения только для этих колонок; базовые
поля сотрудника не могут быть подменены через запрос прав.

Новые кадровые действия выполняются POST-запросами, включая чтение списка:
учётные данные текущего пользователя не попадают в URL. Каждое действие передаёт
`actorLogin` и `actorPassword`; GAS проверяет их через лист `Сотрудники`, статус
`Работает` и право `Управление кадрами = Да`. Без успешной проверки ответ — ошибка
без кадровых данных.

Запись идентифицируется номером строки, возвращённым сервером, и неизменяемым
ФИО. Перед изменением GAS берёт script lock и перепроверяет ФИО в строке. Это
защищает от одновременных правок и от обновления другой записи после перестановки
строк.

## GAS-контракт

Все действия доступны через текущий ERP Web App.

### `personnelList`

Возвращает:

- список отделов и число сотрудников со статусом `Работает`;
- список площадок из листа `Площадки`;
- для выбранного отдела — строки `{ row, fio, position }`;
- для карточки — неизменяемые поля, редактируемые поля и массив
  `{ name, value }` для колонок K+.

Реализация может разбить это на три явных действия (`personnelDepartments`,
`personnelEmployees`, `personnelEmployee`) ради меньших ответов; все используют
одну и ту же серверную проверку доступа.

### `personnelSave`

Принимает `row`, `fio`, редактируемые `platform`, `role`, `login`, `password` и
карту прав. Отдел, должность и ФИО не принимает и не меняет. Логин проверяется
на непустоту и уникальность среди остальных строк. Обновляются только допустимые
колонки; после успеха возвращается свежая карточка.

### `personnelDismiss`

Принимает `row` и `fio`; меняет только `Статус` на `Уволен`. Уволенная учётная
запись больше не проходит вход согласно уже существующей проверке статуса.

### `personnelCreate`

Принимает ФИО, Отдел, Должность, Роль, Площадку, Логин и карту прав. Сервер
проверяет обязательные поля и уникальность логина, создаёт строку, записывает
`Статус = Работает` и пароль.

Пароль генерируется сервером: ровно 10 символов латиницы и цифр; гарантированно
есть минимум одна строчная буква, одна прописная и одна цифра. Возвращённый пароль
показывается после создания в карточке сотрудника.

## Интерфейс

`/personnel` остаётся единым маршрутом и использует состояния внутри страницы:

1. **Отделы.** Карточки отделов с числом работающих сотрудников и последняя
   карточка с `+` для добавления.
2. **Сотрудники отдела.** Кнопка назад и таблица с колонками `Должность` и
   `ФИО`; строка открывает карточку.
3. **Карточка.** Отдел, должность и ФИО показаны только для чтения. Площадка
   выбирается из листа `Площадки`; роль — `Исполнитель` или `Менеджер`; логин,
   пароль и права редактируются. Права отображаются с выбором `Да`/`Нет`.
   Сохранение возвращает к актуальной карточке. Красная кнопка «Уволить» требует
   отдельного подтверждения и затем возвращает к списку отдела.
4. **Добавление.** Отдельная шторка с полями задачи и правами. По успешному
   созданию список и счётчик отдела обновляются, а карточка нового сотрудника
   открывается с сгенерированным паролем.

Экраны используют существующие `ErpScreen`, `ErpGroupedList`, `ErpListRow` и
`ErpActionSheet`; на мобильном карточка и создание открываются как шторки.

## Файлы и проверки

- `scripts/erp-gas-webapp.js` — кадровые действия, проверка доступа и генератор
  пароля.
- `app/utils/erp-sheets.ts`, `types/erp.types.ts` — типизированный контракт API.
- `app/pages/personnel.vue` и небольшие ERP-компоненты — экраны и формы.
- Контрактные тесты GAS: динамические права K+, исключение системных полей,
  уникальность логина, увольнение и пароль из 10 символов требуемого состава.
- Проверки: тесты, `npm run typecheck`, `node --check scripts/erp-gas-webapp.js`,
  `npm run generate`, staging-деплой. Обновление production требует отдельного
  подтверждения.
