# Баланс: выбор площадки для сотрудников Офиса — дизайн

Дата: 2026-07-08
Статус: утверждён пользователем, ожидает implementation plan

## Контекст

Экран `/warehouse-balance` (`app/pages/warehouse-balance.vue`) показывает остатки только своей площадки (`employeeStore.platform`). Сотрудники с площадкой «Офис» должны иметь возможность посмотреть баланс любой другой площадки, а не только своей.

Остальные сотрудники (площадка ≠ «Офис») не затрагиваются — поведение экрана для них не меняется.

## Ключевые решения (из уточняющих вопросов)

1. **Выбор — на самом экране Баланс**, не отдельным шагом перед переходом. Экран открывается как обычно (баланс «Офис» по умолчанию), сверху — переключатель площадки.
2. **Источник списка площадок** — уникальные значения колонки B («Площадка») листа «Склад». Не отдельный справочник, не захардкоженный список в коде.
3. **UI переключателя** — подзаголовок `Площадка: {X}` для Офиса становится кликабельной строкой с шевроном («Площадка: Офис ›»). Тап открывает `ErpActionSheet` со списком площадок (`ErpListRow` на каждую, тот же паттерн, что список категорий в Приёме/Выдаче). Клик по площадке — сразу выбор и закрытие шторки, без отдельной кнопки подтверждения.
4. **По умолчанию** — баланс «Офис» (собственная площадка сотрудника), как и сейчас.

## Архитектура

### Бэкенд: `scripts/warehouse-gas-webapp.js`

Новый GET-action:
```
?action=platforms
```
→ `getPlatforms_()`: сканирует лист «Склад» (колонка B), собирает уникальные непустые значения, сортирует, возвращает `{ok: true, platforms: [...]}`.

Никаких изменений в существующих `stock`/`receiveItem`/`issueItem` — `getStock_(platform, category)` уже принимает произвольный `platform`, менять нечего.

Деплой: сначала staging (существующий staging GAS-проект/деплой), проверка, затем прод — с явным подтверждением перед каждым push/deploy, как обычно.

### Фронтенд

**`app/utils/warehouse-sheets.ts`** — новая функция:
```ts
export async function fetchWarehousePlatforms(): Promise<string[]>
```
GET `action=platforms`, возвращает `platforms` из ответа.

**`app/pages/warehouse-balance.vue`**:
- `isOffice = computed(() => employeeStore.platform === 'Офис')`
- `selectedPlatform = ref(employeeStore.platform)` — площадка, чей баланс реально показан
- `load()` использует `selectedPlatform.value` вместо `employeeStore.platform` напрямую
- Если `isOffice`, при монтировании (параллельно с `load()`) вызывается `fetchWarehousePlatforms()`, результат — в `platforms.value`
- Подзаголовок:
  - НЕ-Офис: как сейчас, обычный `<p>` текст
  - Офис: кликабельная строка с шевроном (`@click` открывает `ErpActionSheet`)
- Шторка (`ErpActionSheet`, `#form` слот): список `ErpListRow` по `platforms.value`; у строки, совпадающей с `selectedPlatform.value`, — иконка-галочка (`heroicons:check`) справа вместо шеврона. Клик по строке: `selectedPlatform.value = platform`, закрыть шторку, `load()` заново.

### Крайние случаи

- `fetchWarehousePlatforms()` падает с ошибкой или возвращает пустой список → подзаголовок остаётся обычным текстом (не кликабельным), экран не ломается, баланс «Офис» показывается как обычно.
- Сотрудники не-Офис не делают запрос `action=platforms` вообще (условие `isOffice` перед вызовом).
- Если у выбранной площадки нет остатков (пустой список) — текст `ErpEmptyState` меняется на нейтральный «На этой площадке нет остатков» (не завязан на «вашей»), подходит и для своей, и для чужой площадки.

## Вне скоупа

- Права доступа/фильтрация «кто может видеть чужой баланс» — только по признаку `platform === 'Офис'`, без отдельной таблицы прав.
- Изменение структуры листа «Склад» — список площадок только читается.
- Персистентность выбора площадки между визитами (localStorage и т.п.) — при каждом заходе на экран показывается своя площадка по умолчанию.
