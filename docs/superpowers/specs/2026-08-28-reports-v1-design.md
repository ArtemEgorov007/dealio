# Отчёты v1 — ежедневный управленческий дашборд

Дата: 2026-08-28  
Контур: staging `erp-mt.online`. Production не меняется.

## Цель

Дать руководителям ежедневную картину по товарной продукции и производству, не меняя действующий процесс: секретарь продолжает обновлять Google-таблицу по будням, ERP только читает и отображает срез.

## Источник данных

- Google Spreadsheet: «Отчеты Секретаря» (`1Y4HcpLRakc-aPWEwfF0PYmo5nzjj_0BLpbzqbtpqHvk`).
- Лист: `Лист15` (`sheetId: 797326975`), первая строка — заголовки.
- ERP не пишет в таблицу, не создаёт строки и не меняет форматирование.
- Считывание проходит через серверный API, а не из браузера пользователя: это не требует предоставлять сотрудникам доступ к Google Sheets.

## Семантика полей

| Поле источника | Смысл в ERP | Единица |
|---|---|---|
| `ТП за месяц, тн` (H) | Товарная продукция за текущий месяц | рубли |
| `Отгружено за месяц, тн` (J) | Отгружено за текущий месяц | тонны |
| `В цехе, тн` (G) | Остаток в цехе на дату среза | тонны |
| `Заказчик`, `Договор`, `Площадка` | Контекст строки детализации | текст |

Колонка H в источнике исторически подписана «тн», однако фактически содержит денежные значения. В ERP она отображается корректно как `ТП за месяц, ₽`; исходная таблица не меняется в рамках v1.

## В объёме v1

### Экран `/reports`

1. Доступ — только при праве `reports` в профиле сотрудника.
2. Заголовок «Отчёты», подпись «Текущий месяц» и время последнего успешного чтения данных.
3. Три обязательные сводные карточки:
   - ТП за месяц, ₽ — сумма H;
   - Отгружено за месяц, т — сумма J;
   - В цехе, т — сумма G.
4. Детализация по строкам: заказчик, договор, площадка, три показатели из сводки.
5. Обновление по кнопке без перезагрузки страницы.
6. Отдельные понятные состояния: загрузка, нет заполненных строк, источник временно недоступен.

## Вне объёма v1

- Запись или редактирование отчёта из ERP.
- Автоматическая загрузка по расписанию.
- Исторические периоды, планы, целевые значения, графики и сравнение динамики.
- Перенос данных отчётов в MySQL.
- Изменение production.

## API

`GET /api/reports/current`

Требует действующую ERP-сессию и право `reports`. Ответ:

```json
{
  "updatedAt": "2026-08-28T12:49:00+03:00",
  "period": "2026-08",
  "summary": {
    "productionRub": 30245810,
    "shippedTons": 1061,
    "inWorkshopTons": 841
  },
  "rows": [
    {
      "customer": "Велесстрой",
      "contract": "Линия 3",
      "site": "Волхонка",
      "productionRub": 12250994,
      "shippedTons": 368,
      "inWorkshopTons": 172
    }
  ]
}
```

Пустые значения трактуются как ноль. Числа, хранимые в Sheet в строковом виде с пробелами-разделителями, сервер нормализует до чисел. Ошибки источника не кэшируются как успешные данные.

## Безопасность

- Учётные данные Google/адрес источника остаются только на сервере в переменных окружения.
- Клиент видит только нормализованный ответ ERP API.
- Пользователь без `reports` получает 403; маршрут также не показывается ему в интерфейсе.

## Приёмка

1. Пользователь с правом `reports` открывает `/reports` и видит три карточки и детализацию.
2. Суммы совпадают с заполненными строками `Лист15` по H, J и G.
3. TP показывает ₽, две производственные метрики — т.
4. Пользователь без права `reports` не получает данные API и не видит раздел.
5. При недоступности источника показана ошибка с возможностью повторить запрос; интерфейс не зависает.
6. В ERP не появляется возможность менять Google-таблицу.
7. Production остаётся без изменений.

## Откат

Не выкатывать на production. На staging откатить статический релиз и API-файлы к предыдущему релизу; Google-таблица не изменялась.
