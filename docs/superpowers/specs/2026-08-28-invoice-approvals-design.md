# Согласования счетов v1 — дизайн

## Цель и границы

Добавить в ERP на staging (`erp-mt.online`) рабочий раздел «Согласования» для ежедневного согласования счетов. Источник данных — Google-таблица «Склад», лист `Согласования` (`1GR19_j5tuqQQthlJ7Ok5Z1EFdQKx0g_jjj_tj6R9xUY`).

В scope:

- чтение очереди счетов согласно должности и ФИО вошедшего сотрудника;
- просмотр файла счета по ссылке из строки;
- согласование и отклонение с записью даты в Google Sheet;
- карточный мобильный интерфейс, согласованный с разделом «Бирки»;
- серверная проверка права `approvals`.

Не в scope v1:

- production (`erp-mt.ru`);
- прямой доступ ERP-клиента к Google Sheet;
- редактирование суммы, счета, площадки либо маршрута согласования;
- отмена уже подтверждённого действия;
- SQL-миграция этого журнала.

## Авторизация и безопасность

Раздел и API доступны только активному пользователю с флагом `approvals`, который соответствует столбцу «Право согласования» листа сотрудников.

Клиент обращается только к same-origin API ERP. API повторно проверяет серверную сессию и право `approvals`, передаёт запрос закрытому Google Apps Script bridge. Bridge хранит токен только в Script Properties и не возвращает его ни клиенту, ни API-ответам.

Bridge открыт технически для вызова сервером, но без корректного токена всегда отвечает `forbidden`. Все значения, которые bridge записывает в таблицу, формируются на сервере; клиент передаёт только устойчивый идентификатор строки и намеренное действие.

## Модель строки и фильтрация

Bridge читает заголовки листа и требует следующие столбцы:

| Назначение | Заголовок |
| --- | --- |
| Карточка | `Площадка`, `Отдел`, `Тип`, `Счет`, `Сумма счета` |
| Фильтрация РО | `Согласование руководителя`, `Ожидает РО` |
| Фильтрация ГД | `Ожидает ГД` |
| Просмотр | `Ссылка на счет` |
| Действия | `Отмена`, `Дата РО`, `Дата ГД` |

API использует профиль сессии: ФИО и должность. Сопоставление должности нормализует пробелы и регистр, но привилегированным остаётся только точное смысловое значение `Генеральный директор`.

- Генеральный директор видит строки, где заполнено `Ожидает ГД`.
- Другой согласующий видит строки, где `Согласование руководителя` совпадает с его ФИО и заполнено `Ожидает РО`.

Bridge возвращает только поля, необходимые для отображения, включая номер строки/устойчивый ключ, ссылку и целевой этап. Не подходящие или неполные строки не покидают серверный контур. Отсутствие обязательного заголовка — ошибка конфигурации источника: bridge ничего не записывает и API возвращает временную ошибку.

## Действия и идемпотентность

Карточка имеет два явных действия после свайпа с подтверждением:

- вправо — согласовать;
- влево — отклонить.

Отклонение записывает текущую серверную дату в `Отмена`. Согласование записывает текущую серверную дату в `Дата РО` для руководителя либо `Дата ГД` для генерального директора.

Перед записью API повторно читает строку через bridge и проверяет, что она принадлежит этапу данного пользователя, всё ещё входит в его очередь и не имеет противоположного заполненного поля действия. Повторный идентичный запрос считается успешным без второй записи; противоположное действие или уже обработанная строка возвращает понятную ошибку и карточка обновляется из источника.

После удачного действия карточка остаётся на экране в конечном состоянии: зелёная со статусом «Согласован» или затемнённая со статусом «Отклонён». При следующем обновлении страницы она исчезает из активной очереди согласно фильтру источника.

## Интерфейс

`/approvals` заменяет заглушку экраном состояния загрузки, ошибки с повтором и пустой очереди. Каждая карточка в визуальном языке «Бирок»: единая высота, скругление, светлая граница, мягкая тень и отступы.

Содержимое карточки:

1. `Площадка`;
2. `Отдел Тип` на новой строке, сформированные из отдельных столбцов `Отдел` и `Тип`;
3. `Счет`;
4. `Сумма счета` с локализованным денежным форматом.

Короткий тап, не признанный свайпом, открывает модальное окно просмотра. Для ссылок на PDF используется iframe, если браузер разрешает встраивание; иначе доступна безопасная кнопка «Открыть счёт» в новой вкладке. Пустая или некорректная ссылка показывает объяснение, а не пустое окно.

Жесты имеют альтернативные кнопки действия для устройств/браузеров без touch-свайпа. Перед записью показывается компактное подтверждение с названием действия. Во время запроса карточка блокируется, чтобы предотвратить двойное нажатие.

## Ошибки и аудит

Недоступность Google bridge возвращается как временная ошибка без раскрытия технических деталей и без изменения визуального статуса карточки. Некорректная строка исключается из выдачи и логируется в bridge; вся очередь не ломается. Отсутствие обязательного заголовка считается ошибкой конфигурации источника и безопасно блокирует очередь, потому что bridge не может надёжно определить столбец для записи.

Каждая запись даты одновременно фиксирует в bridge журнал операции: время, действие, ФИО и номер строки. В v1 журнал является техническим, не выводится отдельным ERP-экраном.

## Проверка готовности

- API отклоняет запрос без сессии и без права `approvals`.
- РО видит только собственные строки с заполненным `Ожидает РО`.
- ГД видит только строки с заполненным `Ожидает ГД`.
- Согласование заполняет только корректный столбец этапа, отклонение — только `Отмена`.
- Повторное действие и конфликт не создают вторую запись.
- Карточка, тап, свайпы, отказ и ошибка bridge проверены на мобильной ширине.
- В staging реальные строки проверены без изменения production.
