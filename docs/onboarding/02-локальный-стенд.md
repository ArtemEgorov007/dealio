# Локальный стенд и ручная проверка

Два режима. Выбирай по задаче.

| Задача | Что запускать |
|---|---|
| Правишь вёрстку, логику экрана | `npm run dev` |
| Трогаешь API, миграции, сессии, права | полный стенд с MySQL (ниже) |
| Сдаёшь работу | полный стенд **+ мобильный проход с касаниями** |

---

## Быстрый режим

```bash
npm run dev     # http://localhost:3000
```

Бэкенда нет, запросы уйдут в никуда. Годится для вёрстки, не годится для
проверки сценария целиком.

---

## Полный стенд: та же топология, что на хостинге

Смысл — получить **один origin** (живые куки-сессии), настоящий PHP и настоящий
MySQL. Именно так ловятся баги, которых не видно ни в тестах, ни в `dev`.

### 1. Временный MySQL

```bash
D=/tmp/erp-local
rm -rf "$D" && mkdir -p "$D"
mysqld --initialize-insecure --datadir="$D/data" --basedir=/usr/local
mysqld --datadir="$D/data" --basedir=/usr/local \
       --socket=/tmp/erp.sock --skip-networking --mysqlx=OFF &
mysql --socket=/tmp/erp.sock -uroot \
      -e "CREATE DATABASE erp CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

Сокет обязательно короткий: путь длиннее 103 символов не работает.

### 2. Сборка в режиме SQL

```bash
NUXT_APP_BASE_URL=/ \
NUXT_PUBLIC_ERP_BACKEND_MODE=sql \
NUXT_PUBLIC_ERP_API_BASE=/api \
npm run generate
```

### 3. Конфиг API

Кладём туда, где его ищет `erp_load_config()` — и заодно внутрь `.output/`,
который в `.gitignore`, так что доступы физически не смогут уехать в репозиторий:

> **Повторный `npm run generate` чистит `.output` целиком** — вместе с конфигом
> и роутером. Снаружи это выглядит не как «пропал конфиг»: статика по-прежнему
> открывается, а любой запрос к API отдаёт 500 «ERP временно недоступна», и
> кажется, что сломался фронтенд. Держи копии конфига и роутера вне `.output` и
> клади их обратно после каждой пересборки.
>
> Правки в `public/api/` тоже не доезжают сами: стенд отдаёт копию из
> `.output/public/api`. Быстрее полной пересборки —
> `rsync -a --delete public/api/ .output/public/api/`.

```bash
mkdir -p .output/erp-api-private
cat > .output/erp-api-private/erp-api-config.php <<'PHP'
<?php
return [
    'db' => ['dsn' => 'mysql:unix_socket=/tmp/erp.sock;dbname=erp;charset=utf8mb4',
             'user' => 'root', 'password' => ''],
    'push' => ['cron_token' => 'local'],
];
PHP
```

### 4. Роутер, повторяющий боевой `.htaccess`

```bash
cat > .output/router.php <<'PHP'
<?php
$path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH) ?: '/';
$root = __DIR__ . '/public';
if (str_starts_with($path, '/api')) {
    $rest = ltrim(substr($path, 4), '/');
    if (preg_match('#^(src|migrations|vendor)(/|$)#', $rest)) { http_response_code(404); return true; }
    require $root . '/api/index.php'; return true;
}
if ($path !== '/' && is_file($root . $path)) { return false; }
require $root . '/index.html'; return true;
PHP

cd .output && PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8099 -t public router.php
```

`PHP_CLI_SERVER_WORKERS` обязателен — без него браузер виснет.
`-t public` обязателен — без него статика отдаёт 404.

Миграции применятся сами при первом обращении к API: их применяет фабрика
соединения.

### 5. Данные для работы

```bash
HASH=$(php -r 'echo password_hash("Test1234", PASSWORD_DEFAULT);')
mysql --socket=/tmp/erp.sock -uroot erp <<SQL
INSERT INTO erp_users (id, fio, login, password_hash, role, platform, department, position, status)
VALUES (101, 'Иванов Иван Иванович', 'i.ivanov', '$HASH', 'employee',
        'Колпино', 'Монтажный цех', 'Монтажник', 'Работает');
INSERT INTO erp_user_permissions (user_id, permission_code, allowed) VALUES (101, 'supply', 1);

```

Права — по одной строке на раздел: `badges`, `measurements`, `packing`,
`reports`, `approvals`, `orders`, `supply`, `warehouse`, `handover`, `personnel`.

## Мобильный проход с касаниями

**Обязателен перед сдачей.** Приложение мобильное; десктопный клик и программная
подмена значений не воспроизводят реальное поведение — так были пропущены три
бага подряд.

Через Playwright нужен отдельный контекст с тач-вводом: обычный не шлёт
touch-события.

```js
const mobile = await browser.newContext({
  viewport: {width: 390, height: 844},
  isMobile: true, hasTouch: true, deviceScaleFactor: 2,
})
const p = await mobile.newPage()
```

Дальше только `tap()` и `pressSequentially()` — никаких `evaluate` с подменой
`value`.

**Клавиатура** эмулируется сжатием видимой области (на iPhone занимает ~336px):

```js
await p.evaluate(() => {
  const vv = window.visualViewport
  Object.defineProperty(vv, 'height', {value: 844 - 336, configurable: true})
  vv.dispatchEvent(new Event('resize'))
})
```

**Слушатели ошибок** ставь **после** входа в систему — иначе 401 первой загрузки
даст ложную тревогу:

```js
p.on('pageerror', e => errors.push(String(e)))
p.on('console', m => { if (m.type() === 'error') errors.push(m.text()) })
p.on('response', r => { if (r.status() >= 400) errors.push(`${r.status()} ${r.url()}`) })
```

### Что проходить

Не только свою правку — весь путь, которого она касается:

- вход и попадание в раздел с главного экрана;
- ввод: подсказки, выбор из списка, ошибочный ввод;
- многострочные формы: добавление, удаление, последняя строка;
- отправка и то, что видно после неё;
- соседний экран, куда ведёт кнопка, и возврат назад;
- пустое состояние и состояние ошибки.

И посмотри скриншоты ключевых экранов глазами. Так находится то, чего нет ни в
одном тесте: например, кнопка списка у заполненной строки показывала одну
позицию вместо всего справочника — формально верно, пользоваться нельзя.

## Уборка

```bash
mysqladmin --socket=/tmp/erp.sock -uroot shutdown
pkill -f "php -S 127.0.0.1:8099"
rm -rf .output/erp-api-private .output/router.php
```

Последняя строка не про порядок, а про безопасность: конфиг с доступами не
должен пережить проверку.
