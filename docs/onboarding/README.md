# Онбординг ERP

Пакет для быстрого входа в проект: новый компьютер, новый исполнитель, другой
ИИ-агент. Читается сверху вниз, но каждый файл самодостаточен.

| Файл | О чём |
|---|---|
| [`01-доступы.md`](01-доступы.md) | что за доступы существуют, где лежат, как восстановить |
| [`02-локальный-стенд.md`](02-локальный-стенд.md) | поднять полный стенд и проверить руками, включая мобильный проход |
| [`03-грабли.md`](03-грабли.md) | ловушки платформы, каждая стоила времени |
| [`04-стиль.md`](04-стиль.md) | как здесь пишут код, тесты и коммиты |

Рядом: [`доступы.local.example.md`](доступы.local.example.md) — шаблон приватного
файла со значениями. Скопируй в `доступы.local.md`, он в `.gitignore`.

## Проверить стенд одной командой

```bash
bash scripts/staging-audit.sh
```

Отвечает на «всё ли доехало и всё ли закрыто»: та ли версия на сайте, не торчат
ли наружу исходники и схема базы, живы ли маршруты, чист ли репозиторий. Тот же
набор проверок выполняет CI после выкатки, но здесь его можно запустить руками в
любой момент.

## Точки входа для агентов

- [`AGENTS.md`](../../AGENTS.md) — основной документ, его читает Codex
- [`CLAUDE.md`](../../CLAUDE.md) — Claude Code

Все три ведут в `AGENTS.md`, чтобы правила не расходились. **Меняешь правило —
меняй в `AGENTS.md`**, а в адаптерах только если поменялась выжимка.
